ダリオ・アモデイやサム・アルトマンら業界のトップが、口を揃えて「AIの破滅的リスク」を警告している。

これはブレーキのない車に乗って「この車はいつか事故を起こす危険がある！」と大騒ぎしているようなもので、外から見れば「いや、まずブレーキを物理的につけろよ」という話でしかない。

今のAI開発の現場は、確率で動くブラックボックス（LLM）の周りを、同じく動的でゆるいスクリプト（Python など）で囲み、プロンプトで「悪いことはしないでね」とお願いしている部分が大きい。そんなフニャフニャな足場の上に、自律エージェントだの自己改善ループだのを乗せれば、暴走しないほうが奇跡だ。

少し正確に書いておく。重い計算の中身は C++ や CUDA で、Python はそれをつなぐ役だ。ただ、AIに判断や行動をさせる部分（エージェント）は、Python のようなスクリプト言語で書かれていることが多い。もちろん各社はお願いだけに頼っているわけではなく、隔離や監視も重ねている。それでも足場の弱さは残る、というのが技術者の実感だと思う。

実際、各社の安全性評価の場で、モデルが意図しないネットワークアクセスをしてしまう挙動が多く報告されている。

もちろん言語だけでそのすべてを防げるわけではないが、少なくともその足元にある危険を、言語の側からどう支えるか。 その試みとして、私は新言語「Sprout」を設計している。ただし先に断っておくと、Sprout はすべてを解決するものではない（3節で書く）。

## 1. スクリプト言語で「自己書き換え」を走らせる危うさ

AIが自らコードを生成し、システムをアップデートしていく未来はすぐそこまで来ている。だが、既存のスクリプト言語の環境には構造的な弱さがある。

- **実行するまで破綻に気づけない**：スクリプト言語では、AIが変なコードを書き足しても、実際にその行が実行される瞬間までエラーが分からない。分かったときには、もう壊す操作が動いた後かもしれない。
- **歯止めが効かない**：一度間違った自己改変が始まると、システム全体を巻き込んで連鎖的に壊れるか、静かに間違った動作を続けてしまう。
- **データと命令の区別があいまい**：読み込ませただけのデータが、そのまま実行される命令として効いてしまう。プロンプトインジェクションはこの弱さの一例だ。

「AIが賢くなれば安全になる」のではない。土台となる言語が緩いままでは、どれだけ知能が上がっても危険性は消えない。今の状況は砂の上に高層ビルを建設しているようなものである。

## 2. Sproutのアプローチ：言語の側に「安全の枠」を組み込む

Sprout が目指しているのは、AIがどれだけ自身を書き換えようとしても、越えてはならない一線を、言語の側が自動で弾く世界だ。たとえるなら、空港の保安検査に近い。搭乗前に全員が必ず通る関門があり、そこを通らない荷物は機内に入れない。

- **「動かす前」に検査する**：AIが書き換えたコードは、実行に渡る前に、Sprout に組み込まれたコンパイラ（実行前の検査官）が調べる。型や安全のルールに違反していれば、実行されずに弾かれる。しかも「どのルールに違反したか」の明細が返るので、AIはそれを読んで直せる。
- **検査を通らないコードは、実行する道がない**：あとから監視役が見張るのではなく、検査を経ずに実行系へ届く経路を、最初から作らない設計にする。
- **実行する瞬間にも見る**：破壊的な操作（削除など）には、「元に戻せる地点を作ってあること」と「最近、壊す操作を重ねすぎていないこと」が必須になる。これは書いた時点ではなく、実行する時点の状態を言語が判定する。
- **自己申告は信用しない**：「この操作は安全です」というAI自身の申告は信じない。中身から、言語の側が判定する。
- **自由と制約の両立**：強固な柵があるからこそ、AIはその内側で、いくらでも大胆に自己改善や試行錯誤を繰り返せる。

ここで一点、正直に書いておく。この設計は、まだ完成していない。現在の実装は、実行しながら動かす方式（動的な VM 評価）で、「すべてのコードが必ずコンパイラを通る」構成は、次の版（v1.0）の構想段階にある。設計が先行して、実装が追いかけている状態だ。

## 3. Sproutにできないこと

Sprout は、「評価環境からの意図しない外部アクセス」を防げない。

Sprout が守るのは、言語処理系の内側で起きる、うっかりや雑な自己書き換えの積み重ねだ。OS やネットワークなど、処理系の外側は守備範囲に入っていない。この種の事態は、その外側の話に見える。悪意をもった主体を閉じ込める、という主張もしない。

だから「Sprout があればAIは安全になる」とは言わない。安全は、評価の層、隔離の層、言語の層のように、何層にも分けて作るものだと思う。Sprout はそのうち、言語の層を受け持つ試みだ。

## 4. 「危険だから止める」のではなく「安全な土台をつくる」

Python のような柔軟だが危うい土台の上で、祈るようにAIを走らせる時代は終わりにしなければならない。

AIに自らをアップデートさせるなら、暴走を止めるルールは、人間の注意力や見張り役のAIだけに頼るべきではない。監視や評価はもちろん必要だ。ただ、見張る側が見落とした瞬間に終わる仕組みでは足りない。ルールは、言語という最も根本の層にも刻み込んでおくべきだ。それが、私が Sprout を設計している最大の理由である。
